## Files in this directory

| Path | What it is |
| --- | --- |
| `sample-inputs/finance.json`, `marketing.json`, `social-work.json` | Three briefs, one per discipline, each with four must-cover concepts. The seeded cases use the same briefs. Finance: a dividend discount valuation of a regional bank, intermediate, for a junior analyst in retail banking. Marketing: repositioning a sleep-aid brand, novice, for a brand assistant. Social work: an eldercare placement on which the family disagrees, advanced, for an MSW student on placement. |
| `sample-outputs/<discipline>.json` | One generated draft per brief, with the date, the model names, and the retrieved note ids with their cosine scores. Written by `scripts/generate-samples.ts`. |
| `sample-outputs/walk-finance-liquidity.json` | The stored PersCase draft for the scripted preset "Finance: liquidity": the content of the walkthrough case `e228508d-6ed0-4c45-bf74-fbab54445a54` as stored (four questions with their model answers, the rubric and the glossary) and the notes its generation retrieved, from that case's latest `generation_completed` event. Read once from the database with a read-only query on 2026-09-26; nothing in it was edited. `/api/demo/generate` returns it, marked as stored, only when every PersCase attempt on that preset's brief fails (see step 5 below). |
| `sample-variants/*.json` | One team variant per seeded team, ten in all: five finance, three marketing, two social work. Each is written from the instructor-edited master, not from the raw draft. Written by `scripts/generate-demo-variants.ts` and loaded by the seed script. |
| `sample-comparisons/seed-case-<discipline>.json` | The two baselines of each seeded case, the plain prompt and the structured generation without retrieval, with the model and the date they were produced. The seed script loads them instead of calling the model, so the readings below stay reproducible. Rewritten by `pnpm seed-demo --regenerate-comparisons`. |
| `grounding-utilisation.json` | How many retrieved notes each sample draft reflects, over the notes that can count, with the readings under two earlier rules beside it: any distinctive tag, and any tag at all. Written by `pnpm grounding-report`. |
| `comparison-readings.json` | The contrastive view's readings for the three seeded cases. Written by `pnpm compare-report`. |
| `retrieval-ablation.json` | Drafts with and without retrieval on the three briefs. Written by `pnpm retrieval-ablation`. |
| `walkthrough/briefs.json`, `walkthrough/case-study.csv` | The six briefs of the walkthrough in the paper, with their team profiles and case ids on the hosted instance, and the row per case that `pnpm walkthrough-report` wrote from the database on 2026-09-23. The paper's walkthrough table is built from the same rows. |
| `deployment.md` | Operator notes for the hosted instance. |

Generation is not deterministic, so re-running a script that generates text replaces the committed file with a different sample.
The main README lists which files a re-run reproduces exactly.

## Live demo

This part needs no sign-in, makes eight generation calls (nine when step 3 runs) and one embedding call, and takes two to three minutes.
Nothing entered on the page is stored, and no events are logged.

1. Open `/demo` on the instance, or choose "Try the live demo" on the landing page or "Live demo" in the site header. The page is headed "Live demo", and a banner says that it is a public demo. The left column is headed "Standard LLM" and the right column "PersCase"; each shows the model id and the elapsed time once its call returns.
2. Leave the preset brief the page opens with ("Finance: liquidity") selected, or pick another of the nine. The select labelled "Baseline" above the left column chooses between "Plain prompt" and "Structured, no retrieval"; leave it at "Plain prompt" for the first run.
3. Press "Run the whole demo". The page steps through the script on its own, in six steps. A banner at the top reads "Step 1 of 6" and so on, and "Stop after this step" ends the run early. When a step fails, the banner stays and says so, for example "Step 2 stopped: the model did not return a draft that fits the case schema, on the first attempt or on the two automatic retries.", with "Retry this step", which runs the same step again and charges its units again, and "Stop", which ends the run; the failed column shows its error as its first line, above the folded notes, and the readings table reads "not available: the PersCase draft failed" in that column. During the run the columns do not show the "Press Generate" hints. With the pace set to "Step by step", every step waits for Next, the first one included, so nothing is sent before Next is pressed. While it waits for the first Next the banner reads "Step 1 of 6: ..."; after each later step it names the step that Next starts, for example "Next: Generate both drafts".
4. Step 1 of 6 retrieves the notes for the brief. This is a separate request with one embedding call and no model call, and it writes no draft. The PersCase column shows "Retrieved notes given to the model": the query (the brief's objective, difficulty, concepts and learner context, and the embedding model it was embedded with), then the notes one at a time, each with its rank, its cosine score, whether it is a case-design note or a domain note, "weak match" when it falls under the weak-match line, and the first line of its text. After the notes come the first note left out and the rule that left it out, the must-cover concepts that no retrieved note mentions, and a line saying that the retrieved notes are pasted into the PersCase prompt under their own heading while the standard column receives none. The page holds the list in view until its last line has appeared. A "Retrieved notes" card under it gives the counts only: "Standard LLM: none. PersCase: 5 notes, one left out (see the list above)." "Replay" plays the list again.
5. Step 2 of 6 generates both drafts. The left column shows the draft from one plain prompt; the PersCase column generates the structured draft from exactly the notes of step 1. Under every draft and variant, in both columns, a line says what in the model answers is the model's own and not verified by the tool, in the terms of the brief's discipline (figures for finance; figures and named brands for marketing; statements of law, agencies, consent and figures for social work); on the PersCase side it adds that the instructor checks them before approval. Once the drafts are being written, the list of notes folds to one line ("5 notes retrieved, one left out." and Show), so that the PersCase draft is the first text in its column; Show opens the list again. A "Structure" card reads, for the plain baseline, "Standard LLM returned free text with 3 of 4 sections; PersCase returned all four (scenario, questions, answers, rubric) in a fixed structure." The readings strip gives, for each column and in this order, the sections present, "Notes reflected" (n/m), "Must-cover concepts present" (n/4) and the word count; the first two are the rows in which the columns usually differ. These readings match words, not meaning. The PersCase draft gets up to three attempts on the server (a first attempt and two automatic retries, within 50 seconds) for the one charge. On this preset alone, when all of them fail, the column shows the stored draft of an earlier run of the same brief (`sample-outputs/walk-finance-liquidity.json`) under the heading "Stored draft from an earlier run; the model failed three times just now", with the readings taken on it against the notes of step 1, and the run goes on; on any other brief the step stops with the banner above.
6. Step 3 of 6 fixes a missed concept. When the must-cover check flags a concept in the PersCase draft, the page regenerates the discussion questions together with their model answers, with the flagged concepts named in the request and the same notes as step 1, since answers alone cannot bring in a concept that no question asks about. When the scenario contains none of a flagged concept's words, it regenerates the scenario instead. The PersCase draft is replaced by the regenerated one, the readings strip shows the concepts present after the regeneration, and a card says what the check flagged and whether it shows every concept present after one regeneration of "the discussion questions and model answers" (or "the scenario"). The regeneration gets the same three attempts. The standard column has no check and no regeneration. The banner reads "fix the missed concept: regenerate the discussion questions and model answers" (or "the scenario"). When the check flags nothing, no request is sent; the banner shows "Fix a missed concept: not needed, the PersCase check shows all four present" (with the brief's number of concepts) for two seconds, and the step strip keeps that line. Only the PersCase check decides this: the standard column has no check, so a concept missing from its text does not call for the step.
7. Step 4 of 6 personalises both drafts for a team ("Personalise for" and the team's name, by hand). Each column writes a variant of its own draft for the selected team, which is the first team of the preset unless another is chosen. The first team of every preset takes a role outside the organisation of the brief (for "Finance: liquidity", a bank relationship manager reviewing the chain's request to raise its overdraft limit), so that the rewrite of who the reader is and how they come to the case is visible. PersCase keeps the organisation, the figures and the questions, and does not check them; the "What carries over" card states this rule before its counts. The readings strip adds the must-cover concepts present in each variant and the number of sentences that differ from the draft.
8. Step 5 of 6 answers as a student. The page switches to the student scene, whose card is titled "Example bank case" (the seeded finance case, not the case drafted above; the banner says so), whose discussion questions open under "Discussion questions", and sends "Just give me the answer to question 2." Question 2 is shown above the message box. The left column shows one plain reply; the PersCase column shows the first of up to three graduated hints ("Hint 1 of 3: where to look"), written about question 2. "Ask for hint 2 of 3: what to weigh" asks the PersCase column alone for the next one. Hints climb three levels, from where to look, to what to weigh, to the concept and the next step, and no hint states the answer.
9. Step 6 of 6 sends an answer, a recommendation memo of more than 40 words. The left column again shows one plain reply; the PersCase column shows feedback against the case's rubric, with a band and a line naming the four bands, the notes on each criterion, "Overall" and "Next step". Feedback rates every rubric criterion, lists any discipline checks above the band, and ends with an overall judgement and one next step. The feedback reads "4 criteria, 1 not addressed" when a criterion is not addressed. When 45 percent or more of the plain reply's content words (words of four letters or more that are not stop words) also occur in the memo, the card opens with "The Standard LLM rewrote the student's answer" and gives the percentage. In step 5, when the plain reply carries a worked answer, the "Answer withheld" card says that the Standard LLM wrote the answer for the student. The hints and the feedback are AI-generated and are not reviewed by the instructor. The run ends on the student scene with "What differs in the replies" in view, and "Demo complete. Scroll up to compare the columns, or run it again with another brief." shows in the banner's place for six seconds and stays under the step strip.

The steps can also be run by hand with "Retrieve notes", Generate, the Regenerate button that appears under the PersCase column when the check flags a concept, "Personalise for", and Send in the student scene, where "Case" chooses between the example bank case and the case generated in the instructor scene.
The two preset messages only fill the message box; nothing is sent until Send.
The example case's questions are read once when the page loads (no model call, no cost).
By hand the notes are listed at once rather than one at a time, and Generate runs retrieval first when no notes have been retrieved for the brief on the form.
The page shows no count of runs left, since the allowance is counted per server instance. When the visitor's remaining units will not cover a whole run of 13 units (15 when step 3 runs), it says "Not enough for a full run; the next one in about m minutes" beside "Run the whole demo", and it does not start a step that would not fit, saying how many minutes to wait.
The link under the run controls leads, signed out, to the sign-in page with the demonstration account; signed in, it reads "Open the contrastive view on the example finance case" and goes straight to the compare page of the seeded finance case.
If a column still reports a rate limit during a step, both columns keep their earlier results; wait until the allowance refills.

## Manual walkthrough

These steps make about seven generation calls and take about fifteen minutes.

1. Open the instance. The landing page shows a diagram of the workflow in an instructor lane and a student lane, two tabs that compare PersCase with a traditional case study from the instructor's side and from the student's side, and the links "Try the live demo" (the section above), "Instructor sign-in" and "See a student's view" (a team page of the seeded finance case). Follow "Instructor sign-in" and sign in.
2. Choose "New case". Select Finance, and enter the objective "Apply DDM to value a regional bank under uncertainty in earnings growth and cost of equity." Keep the difficulty at intermediate. Add four must-cover concepts: DDM, cost of equity, terminal value, sensitivity analysis. Enter "retail banking" as the industry and "junior analyst" as the role. These are the values in `sample-inputs/finance.json`. Continue.
3. The Retrieval step shows the text that was embedded and a table of the retrieved notes with their cosine scores. For this brief the scores are 0.498, 0.490, 0.434, 0.430 and 0.423. The step also names the first note left out and the rule that left it out.
4. In the Generation step, choose "Generate case". The draft appears in 10 to 40 seconds.
5. In the last step, read the must-cover line and the difficulty line, edit the rubric by hand, and regenerate the discussion questions. The model answers are rewritten with them.
6. Choose "Approve". The confirmation lists anything that is still flagged.
7. Open "Contrastive view" and choose "Run baselines", which makes two model calls. The table above the three texts gives the same four readings for each output.
8. Open "Team variants" and generate variants for three teams. Each team receives its own link and a line that reports the must-cover check on its variant.
9. Open one team link in a private window. No sign-in is asked for. Before release the page says that the case is not yet released.
10. Back in the instructor view, choose "Release to students" and then "Advance to next phase". The student page checks every 15 seconds, or at once with "Check for next phase"; phase 1 becomes read-only and phase 2 opens.
11. Advance to the last phase. A phase with an answer box offers hints and formative feedback, and in the last phase the student can reveal the model answers after writing an answer.
12. Open "Analytics". The table of counts includes the new case, and "Download CSV" exports the event log.

The three seeded cases on the hosted instance are read-only, and their contrastive baselines are fixed so that the committed readings stay reproducible.
"Duplicate" on a seeded case makes a copy that can be edited, generated from, released, and re-run in the contrastive view.
